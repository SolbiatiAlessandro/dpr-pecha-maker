WEB PECHA MAKER — FIRST-PASS COMPATIBILITY
Updated 2026-11-23

This is an independent Unicode web implementation inspired by the public Windows PechaMaker documentation. It is not an exact port, and no proprietary implementation or assets are reused. Original Windows runtime equivalence has not yet been verified. Different typefaces and shaping can produce different line and page breaks.

AVAILABLE IN THE WEB APP
- Fixed page images: six box/text-side anchors, shifts, text exclusion margin and per-page assignment. Anchor coordinates and text overlap rules still need Windows comparison.
- Embedded PNG inline images and image yi-go, scale/DPI, baseline adjustment, side spacing and PNG download. Explicit inline copy/move commands share embedded pixels and reset spacing/scale; raw text-token clipboard edits do not. PNG metadata is read; absent/ignored DPI uses a web default of96. Static analysis shows Windows uses reference-display logical units, not a fixed96DPI constant; its display-dependent rounding remains unmatched.
- Title/Fancy/Body page types, opening counts, lines, fixed line heights, box styles, colours, margins and insets.
- Paper dimensions and orientation, four margins, top/center placement and pages per sheet.
- Independent Tibetan folio and Arabic page starting numbers, title visibility, Jyon, fixed folio phrase, independent number fonts, sizes and insets.
- Arabic bottom/center placement and label rotation; extra Tibetan label rotation choices.
- Static margin annotations for page type and front/back, with optional mixed font/style/colour, one size per annotation position, and inset.
- Compact page view removes gaps/captions and disables app print buttons until turned off. Browser-level print commands still generate the normal sheet layout.
- Optional font kerning where the browser supports matching canvas measurement and SVG rendering. Native font metrics remain unverified.
- Left/right/center/justified text, font size and colour, bold/italic/underline/strike formatting marks, hard returns, hard page breaks and fixed shad.
- One tab interval with tab-aligned text, shared line baselines for mixed-size text, independent Tibetan raise, and nonprinting baseline/page-type-colour guides. Native page-type first-baseline offsets now import from BaseLineAdj; historical font metrics still need comparison.
- Automatic yi-go, Rinchen/Yang shad options, and final dzog thik with separate segment heights and inch/whitespace-percent rise controls. Exact edge behavior and whitespace endpoints still need Windows comparison.
- Duplex/manual/proof print preparation, reversed back rows, optional reverse back sheets, cut marks and test-sheet mode. Physical printer calibration remains necessary.
- Browser autosave, full web document save/open, separate web layout/content/annotation files. New text and text/PDF/RTF imports retain annotations, yi-go and fixed folio phrase.
- Unicode RTF body export with fonts/styles/colours and inline PNGs. Automatic marks, labels, page-attached images and pecha layout are excluded; inline image baseline/side spacing is not preserved by this exporter. RTF readers need suitable Tibetan fonts.

ADDED WEB WORKFLOWS (NOT CLAIMED ORIGINAL WINDOWS FEATURES)
- PDF extraction, legacy-font conversion where tables exist, Tibetan OCR and text repair.
- Unicode Tibetan and Wylie entry.
- Reversible whole-main-text size override that preserves fonts, bold and colours.
- Configurable root/commentary/heading styles. No fixed tradition-specific bold mapping.
- Ordered texts within a volume, independent Tibetan starts, continuous Arabic page numbers, section side names and text reordering.
- In pecha mode each section starts on a new folio front; an inserted blank back counts toward volume page numbers. Full-page mode starts a new page without a blank back. Restarting Title/Fancy layouts is an explicit per-text choice.

PARTIAL COMPATIBILITY
- Character selection: a Unicode Tibetan palette groups letters, subjoined forms, marks, signs and numbers, with optional supported typeface choice. It inserts at the cursor or replaces selection while preserving surrounding formatting. It does not reproduce legacy font-code charts or all Windows-installed fonts.
- Full-page (non-pecha) mode reflows within paper margins, with separate line height and first baseline, one page per sheet, and yi-go after the first page. Pecha frames/labels are retained but hidden; original label interactions and native font/print equivalence still need verification.
- RTF body import retains Unicode, common single-byte code pages, mixed font/style/colour, breaks and PNG images while preserving current layout/notes. Tables are flattened; non-PNG pictures and embedded objects are skipped. Multibyte code pages, paragraph geometry and exact source font metrics remain incomplete.
- Custom yi-go accepts formatting marks; its font/emphasis can differ from the body, its size follows the first character, and its colour can follow that character or its own runs. Exact legacy rich-text paste behavior remains unverified.
- PXP import: five public examples are exercised, but not all settings, old font runs or images survive. Textual native image-header1.1 imports embedded PNG inline, yi-go and fixed-page images experimentally; version1.0 supports the observed28-byte asset/40-byte inline records. Six page anchors and one-based physical page numbers follow static format evidence. Framing/reference tests and browser import QA use synthetic specimens; no real native image specimen has been verified. Import notes remain visible above the preview during the session. No binary-format round trip is promised.
- Experimental PXT/PXC/PXA loading preserves the documented layout/content/annotation scopes. Scope handling is regression-tested with synthetic fixtures; native partial-file exports still need Windows verification.
- Editing: uses text plus visible formatting marks. The selected-text attribute panel changes only specified attributes, preserving mixed fonts, colours and styles and restoring the following text. It is not a direct-page WYSIWYG editor. Quick formatting chips still insert marks that continue until changed.
- Annotations: mixed runs use visible formatting marks rather than the original rich-text paste interface. Known native annotation formatting codes are imported; exact legacy fonts and all codes remain unverified.
- Templates: web .pecha JSON files only; they are not Windows .pxt/.pxc/.pxa files. Layout saves do not contain text or annotations; annotation saves contain numbering.
- Printing: browser print/save-PDF. Match the paper size and orientation, use 100% scale and no margins, and disable browser headers/footers. Browser and printer settings can otherwise add pages or alter alignment.

NOT IMPLEMENTED YET
- Native image export, unobserved older record sizes, hidden native centered-page-image slot3, and exact original clipboard image semantics.
- TibetDoc/DCT import/export; Windows PechaMaker binary-format export.
- TCC/Sambhota legacy keyboard maps and locked keyboard mode.

- Configurable timed recovery/revert controls, command-line imports, original Close/startup-defaults workflow.
- Typeover/format-code navigation, original direct-page editing and structured multilingual columns.
- Arbitrary page rearrangement within a text; reordering is by whole text section.

STILL TO VERIFY AGAINST WINDOWS
Exact Tibetan folio facing direction; rotation conventions; pagination and legacy font metrics; shad/yi-go/dzog edge cases; rich annotation behavior; all file-setting semantics. Missing documentation is not proof that a feature is absent from Windows.

Reference sources: https://www.pechamaker.com/FAQ.html and the official User's Guide, release history and public discussion forum at https://www.pechamaker.com/.
