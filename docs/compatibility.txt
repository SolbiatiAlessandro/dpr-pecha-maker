WEB PECHA MAKER — FIRST-PASS COMPATIBILITY
Updated 2026-11-26

This is an independent Unicode web implementation inspired by the public Windows PechaMaker documentation. It is not an exact port, and no proprietary implementation or assets are reused. Original Windows runtime equivalence has not yet been verified. Different typefaces and shaping can produce different line and page breaks.

AVAILABLE IN THE WEB APP
- File drops share the Open import path. Cancelling TibetDoc settings or failing to read a file keeps the current document and editing view; overlapping imports are rejected until the first finishes or is cancelled. Non-file text drags are left to the browser. Original Windows drag/drop details remain unverified.
- Experimental RTF PNG cropping preserves four edges, negative blank borders and independent scaling. The visible rectangle drives wrapping, alignment and preview/print clipping; original PNG bytes stay intact. Save, RTF inline export/paste and inline copy/move retain crops. Invalid or excessive crops are ignored with a notice; images too small for RTF twip precision are rejected on export. Windows PXP/PXC export rejects used cropped images until native representation is verified. PNG download returns the full original image. Native crop semantics, richer shape cropping and exact original rendering remain unverified.
- The character picker offers document fonts from body text, all sections, rich marks, numbering and configured styles, plus bundled Tibetan typefaces. Fonts remain available after text is removed during the editing session; full document/body imports reset this history, while layout/annotation-only imports preserve it. History is not stored in Save files. The chart preview follows the selected typeface or the font at the insertion point, including role styles. Local fonts can fall back in the browser; converted legacy source names and original Windows font-history behavior remain unverified.
- Native and RTF imports recognize Dedris names through the existing Ededris maps, Sama/b/c through Esama/b/c, and the historical Dedris-syma/Ededris-syma names through Ededris-sym. PDF conversion and character charts share these aliases. Existing unmapped glyphs remain unresolved and reported; source font appearance, keyboard maps and exact Windows behavior remain unverified.
- Character charts cover 66 legacy font maps under 103 recognized names and aliases, including TibetanMachineWeb, Ededris, Esama, LTibetan/LMantra, TCRC and dBu-can variants. Only mapped Tibetan sequences and space are insertable; unresolved, empty, ambiguous and non-Tibetan slots remain disabled. Charts insert Unicode equivalents, not original font bytes or interactive keyboard mappings. Original glyph shapes, complete font coverage and original font-history persistence remain unverified.
- Fourteen malformed Ededris character mappings no longer insert conversion-table source text. These unresolved slots produce replacements and a warning in RTF imports; native imports omit them and report unsupported characters. PDF conversion also omits them. Their intended glyphs, conflicting conversion references and original appearance remain unverified.
- RTF file import and formatted paste omit content explicitly marked hidden (\v), including its text, pictures and page breaks, with a visible omission notice. Group boundaries, explicit visibility and plain-format resets restore visibility correctly; Unicode fallback remains scoped. Hidden-only paste preserves the selection. Hidden content is not retained in the web document, and stylesheet-derived hiding, revision visibility and original Windows behavior remain unverified.
- Experimental PXC page-image export supports all six anchors and shares PNG payloads with inline/yi-go images. It recalculates the source web page count and omits placements assigned beyond it, reporting the count without changing the editable document. Full PXP export retains future-page assignments. The receiving layout remains separate; exact Windows pagination/pruning, positioning and opening remain unverified.
- Experimental PXP/PXC/PXA export now supports exact BMP characters representable in Shift-JIS, Windows Korean, GBK and the Windows Big5 area, alongside the existing single-byte charsets and TCC conversion. Characters remain contiguous across byte pairs; body, yi-go, folio phrases and annotations use the appropriate font charset. Unsupported Unicode, replacement and private-use glyphs still reject before download. Decoder extensions and duplicate byte mappings may differ from a particular Windows installation; native opening, fonts and line breaking remain unverified.
- Locked keyboard font for direct Unicode typing and completed input-method composition, toggled with Ctrl/Command+K in the editor. Separate remembered font/size/colour/emphasis choices apply across cursor positions; ordinary font-formatting controls are disabled while locked. Following text keeps its style, combining marks stay with their base, and Typeover can be combined with locked typing. Supplied RTF paste keeps its own styles. Whole-text size overrides the locked size until cleared. Full document/body replacement starts in Normal mode; layout/annotation imports retain the mode. Composition formatting may add a separate undo step. Legacy TCC/Sambhota mapping, original IME/undo behavior and native runtime equivalence remain unverified.
- Experimental PXP/PXC/PXA export encodes Windows1250–1258 and Thai874 text using native font charset records, including separate records for one family used with multiple encodings. Applies to body, yi-go, fixed folio phrase and static notes according to file scope; Tibetan retains the TCC conversion. The original document is unchanged. Font names remain limited to the existing Windows-1252 subset; Unicode outside the supported single-byte and East Asian repertoires still rejects before download. Native font availability, mixed-script shaping, right-to-left layout and Windows opening remain unverified.
- Experimental Windows PXP document export combines supported text/automatic marks with native paper, margins, pecha geometry, page types and numbering layout. The Arabic page-number face has a portable full-file font reference. Inline, yi-go and page-attached PNG images are included; unsupported text is rejected; Tibetan folio font selection, web print options, style definitions and volume metadata remain limited. Automatic baselines become fixed and native font metrics need comparison. Full PXP imports clear a prior web text-size override so stored run sizes can render. Original Windows opening remains unverified.
- Experimental Windows PXC content export: body styles/sizes/alignments, line/page breaks, mapped Tibetan TCC and supported Windows single-byte or East Asian text, static notes, fixed folio phrase, counters, yi-go, shad and dzog settings. Uses native binary framing, full font records and the checksum corroborated by all five bundled original PXP files. Page-attached images within the source web page count are included; later assignments are omitted with a note. Unsupported characters are rejected before download. PXC import clears any prior web text-size override so stored native run sizes render, with a note when an override was present. Receiving layout/number sizes/fonts/spacing remain separate; volume metadata, flow wrapping, implicit page-type sizes and native typography are not preserved exactly. Original Windows opening remains unverified.
- Experimental Windows PXA annotation export: static notes, fixed folio text, counters and outside spacing; mixed emphasis/colour, supported Windows single-byte or East Asian text and mapped Tibetan TCC glyphs. Native encoded-size/font limits and unsupported characters are checked before download. Numbering fonts are omitted; lower-left notes share native settings and back lower-left slots are omitted with warnings. Size rounding, font substitutions, disabled-counter conversion and rotation differences are reported. Original Windows opening/visual fidelity remains unverified.
- Unicode RTF fallback text is skipped without applying its formatting or losing the following real characters. Control words, symbols and binary tokens count correctly; group boundaries end skipping, including ignored destinations, pictures and dual ANSI/Unicode representations. Scoped fallback lengths, font names, Tibetan/emoji, file imports and paste are regression-tested.
- RTF imports with an absent font0 use the first declared font, preserving declaration order, charset decoding and known Tibetan mappings. This also applies after plain-format resets and explicit font0 references, including raw multibyte bytes. A comparison notice is shown; arbitrary missing nonzero IDs and exact Windows rendering remain unresolved.
- RTF font-table parsing separates primary font names from nested classification, alternate-name and embedded-font metadata. Grouped/flat entries and scoped Unicode font-name fallbacks are tested. This preserves named-font selection and recognized Tibetan legacy conversion in these files. Alternate-font selection, embedded-font loading and native runtime equivalence remain unverified.
- RTF import and paste honor per-font charsets (Windows1250–1258, Thai874, Mac Roman, Shift-JIS, GBK, Korean949 and Big5), plus UTF-8 document bytes. Explicit per-font code pages (\cpg) override charset hints for body text and primary font names; nested embedded-font/file metadata does not change the surrounding font encoding. Consecutive encoded bytes are decoded together. RTF-J raw Shift-JIS/GBK/Korean/Big5 lead bytes consume their raw trail byte before braces or backslashes are interpreted as RTF syntax. Header/per-font encoding, group restoration, Unicode fallback and raw font names are covered. Escaped lead bytes support raw ASCII or escaped trails; raw leads followed by escaped trails are invalid RTF. Font switches/group restoration, encoded font names and Unicode fallback are supported. Known legacy Tibetan font mappings take precedence. Unsupported encodings, invalid/incomplete sequences and undefined bytes are visibly replaced and reported; native Windows rendering, associated/composite-font runs, unsupported code pages and full RTF fidelity remain unverified.
- Native PXP/PXC/PXA font charset decoding for Mac Roman (charset77), Windows single-byte code pages1250–1258 and874 plus Shift-JIS, GBK, Korean949 and Big5, including body, annotations, yi-go and fixed folio text. Consecutive multibyte text is decoded together; formatting/font changes, structural controls and framed single-glyph records end a sequence. Undefined/unsupported bytes are visibly replaced and reported. System-default charset uses1252 with a locale warning; Mac Roman body text, framed glyphs, notes, yi-go and fixed folio text retain Unicode through Save/RTF; original Mac-font glyph shapes and private-use symbols need comparison. Johab, other Mac/OEM and symbol/custom encodings, real native charset fixtures and exact Windows text layout remain incomplete.
- Native PXP/PXC/PXA strikeout on/off and explicit black text are preserved, including rich annotations and pages with a coloured default. Synthetic import, Save/Open, RTF and preview/print tests pass; original Windows visual parity remains unverified.
- TibetanMachine and Skt1–4 byte imports and character charts include missing Windows-1252 slots already represented by Unicode keys in the public conversion tables. Explicit existing byte mappings take priority. Native exports use only valid byte slots, preventing Unicode aliases from being truncated into different Tibetan glyphs. Other legacy families and actual Windows rendering remain unverified.
- Native body and annotation font families are retained, including temporary single-glyph font changes. Known legacy Tibetan fonts convert to Unicode with Jomolhari substitution. Named families survive web Save, size-only edits and RTF export/import; local font availability and fallback metrics affect rendering. Annotation positions still use one size each. Exact Windows fonts and layout remain unverified.
- Native PXP/PXC yi-go font and colour runs are retained, with size following the page's first character. The current colour-matching choice survives import; explicit empty streams clear the ornament. Save/Open, page eligibility and preview/print are tested. Original Windows visual/font equivalence remains unverified.
- Fixed-folio phrases have a separate enable toggle and optional formatting marks. Native PXP/PXC/PXA imports retain disabled phrases and mixed font/style/colour runs. Enabled phrases appear on every front, including Title pages and zero numbering starts; empty phrases stay blank. Older plain web phrases migrate without interpreting braces. Save, scope, rotation and preview/print tests pass; Windows visual parity remains unverified.
- Experimental DCT single-body import accepts modern PKTC version 5 and numeric TibetDoc versions 2–5, with five or six whitespace-separated numeric settings fields. Numeric variants are tested with synthetic fixtures derived from the observed format, not genuine older documents. Versions 2/3 normalize older base/subfont byte positions once before Unicode conversion; unresolved corrected slots use visible replacements and an explicit warning. Unknown versions and multi-record formats are rejected. Center/left toggles and their native line boundaries are retained; other source layout/styles are not reproduced. CSX+ diacritics convert 124 high-byte positions to Unicode (90 extended positions plus the existing 34 core positions), with optional TibetDoc remapping and separate font/size choices. Rings below, candrabindu and combined accents retain their distinctions. With remapping off, byte209 is i-tilde; with remapping on it follows the native N-tilde remap. Unspecified slots160/202, unresolved underlined digraphs200/204, symbol and unmapped glyphs use visible replacements. Original CSX+ font appearance and accented real-file specimens remain unverified. Public fixture tested, with a known opening-ornament mapping discrepancy explicitly warned. A cancellable import dialog chooses Tibetan legacy size and independent named Latin/diacritical fonts and sizes, inherits the current Tibetan web face, and remembers successful choices. Fresh Latin preferences use Times New Roman; existing preferences are retained. Unavailable local fonts use browser fallback. Native Windows equivalence, font metrics and complete diacritic/symbol coverage remain unverified.
- RTF PNG import and paste preserve independent horizontal/vertical percentages, including a missing axis defaulting to 100%. Physical dimensions survive Save and RTF export via per-axis DPI. Invalid scales default with a notice; dimensions outside the supported scale/DPI range are adjusted with a warning. Rectangular PNG cropping is experimental (see below); non-PNG pictures and exact native appearance remain incomplete.
- RTF image-first/image-only paragraphs retain left, center, right and justified alignment through import/export, including inherited import formatting and group restoration. Browser preview and print geometry are tested; exact original Windows behavior remains unverified.
- Independent horizontal/vertical image DPI from PNG metadata and native records, with matching preview/print geometry and RTF goal-size round trips. Blank vertical DPI follows horizontal for older web files. Ignore DPI, or either missing native axis, uses96 on both axes. PNG uploads retain original bytes/metadata for PNG download; placement overrides are saved in web documents. Native display rounding and real-file comparison remain unverified.
- Direct JPEG insertion preserves JFIF inch/cm or Exif resolution through PNG conversion, including independent axes and browser-applied Exif rotation/mirroring. Valid main-image Exif resolution takes precedence over JFIF; invalid/missing absolute density keeps the web96DPI fallback. Converted PNG downloads retain density to PNG's integer pixels-per-metre precision. Insertion reports density clamping to the supported10–2400DPI range. Original Windows JPEG orientation, metadata precedence, colour profiles and missing-density behavior remain unverified; other FreeImage formats and non-PNG RTF pictures remain incomplete.
- Direct GIF and BMP insertion converts browser-decoded pixels to PNG. GIF transparency and the first animation frame are retained. Windows BMP INFO/V2/V3/V4/V5 density fields preserve independent axes; unsupported headers or absent/nonpositive density use the web96DPI fallback. Byte signatures identify supported formats even when the system MIME type is missing or incorrect. Browser-supported BMP variants are accepted; OS/2/RLE/bitfield coverage, native GIF frame/background selection, colour profiles and original Windows decoding remain unverified. Other original FreeImage formats and non-PNG RTF pictures remain incomplete.
- Direct Targa insertion accepts raw/RLE color-mapped, true-color and grayscale images (types1/2/3/9/10/11), 8/16-bit palette indices, 15/16/24/32-bit palette/true-color entries and 8/16-bit gray/alpha. All four origins, image IDs and nonzero palette starts are handled. Original files require a .tga/.targa name; version2 footer signatures identify renamed files. Alpha uses descriptor bits and version2 attribute types, including unpremultiplication. PNG conversion uses the web96DPI fallback; canvas can round partially transparent color channels. Interleaved/reserved formats reject; gamma, pixel aspect ratio, color-correction tables and developer metadata are not applied. Exact Windows decoding/alpha/metadata/display defaults remain unverified.
- Direct PBM/PGM/PPM insertion supports plain P1/P2/P3 and raw P4/P5/P6, header comments, packed monochrome rows and 8/16-bit big-endian samples. The first image becomes an opaque PNG at the web96DPI fallback. Inputs with maxima above 255 retain 16-bit grayscale/RGB samples through PNG download, Save, RTF and native exports; other inputs use 8-bit channels. Scaling to the full channel range truncates fractional values, matching the bundled decoder’s static arithmetic. No colour-space/gamma conversion is applied. A browser without CompressionStream support reports that high-depth insertion is unavailable rather than losing sample precision. Raw headers consume one raster-delimiter byte, preserving following whitespace/# pixels. Original runtime display/gamma/depth retention/default-DPI behavior and sequence handling remain unverified; PAM/PFM and other original image formats remain incomplete.
- Experimental full PXP page-image export includes all six supported anchors, physical document page assignments, shifts, exclusion margin, scale and DPI. It retains assignments beyond the current text and shares PNG assets with inline/yi-go placements. Both native import and export clamp horizontal/vertical shifts below0.01inch, as the original reader does, with an explicit note. PXC exports placements within the freshly measured web page count and reports omitted future-page placements; exact native pagination-based pruning remains unverified. Native reference-display caches, opening, geometry and physical printing still need original application comparison.
- Fixed page images: six box/text-side anchors, shifts, text exclusion margin and per-page assignment. Anchor coordinates and text overlap rules still need Windows comparison.
- Embedded PNG inline images and image yi-go, scale/DPI, baseline adjustment, side spacing and PNG download. Explicit inline copy/move commands share embedded pixels and reset spacing/scale; raw text-token clipboard edits do not. PNG metadata is read; absent/ignored DPI uses a web default of96. Static analysis shows Windows uses reference-display logical units, not a fixed96DPI constant; its display-dependent rounding remains unmatched.
- Experimental PXP/PXC inline and yi-go PNG export uses native image-header1.1, indexed occurrence records, signed CRC32 and concatenated PNG payloads. Scale, independent DPI, side spacing, baseline adjustment, Tibetan adjustment and Ignore DPI are included. PNG density metadata is adjusted when needed for Windows reopening without changing pixels or the editable source; integer DPI/scale rounding is reported. Repeated references get separate native placements; identical pixels with distinct DPI get separate payload variants. PXC page images, invalid/missing PNGs and size/count overflows are rejected. Drawing caches assume a96DPI reference; exact Windows opening, display rounding, positioning and physical printing remain unverified.
- Native PXP/PXC image loading now follows the original PNG reload path: embedded absolute density overrides cached image-table DPI, truncates to whole unsigned16-bit DPI, and retains independent axes. Absent or relative PNG density uses the original bitmap default of72DPI. Explicit zero axes fall back together to web96DPI with a reference-display warning. Direct PNG insertion keeps fractional DPI and its existing96DPI default. Synthetic v1.0/v1.1 fixtures, browser geometry, Save/Open and print/PDF checks cover this distinction; original application acceptance and physical rendering remain unverified.
- Title/Fancy/Body page types, opening counts, lines, fixed line heights, box styles, colours, margins and insets.
- Paper dimensions and orientation, four margins, top/center placement and pages per sheet.
- Independent Tibetan folio and Arabic page starting numbers, title visibility, Jyon, fixed folio phrase, independent number fonts, sizes and insets.
- Arabic bottom/center placement and label rotation; extra Tibetan label rotation choices.
- Static margin annotations for page type and front/back, with optional mixed font/style/colour, one size per annotation position, and inset.
- Compact page view removes gaps/captions and disables app print buttons until turned off. Browser-level print commands still generate the normal sheet layout.
- Optional font kerning where the browser supports matching canvas measurement and SVG rendering. Native font metrics remain unverified.
- Formatting changes inside a word or Tibetan syllable preserve its wrapping boundary. Redundant codes with identical effective font and styling retain kerning and Tibetan shaping in body text, rich yi-go and annotations. Actual style changes remain separate. Rinchen/Yang shad conversion follows a syllable across formatting runs while keeping the mark's style. Original font metrics, cross-font kerning and combining marks split across genuinely different styles still need comparison.
- Nonbreaking spaces stay inside an unbroken span, including across formatting runs and Tibetan syllable boundaries. Oversized spans overflow rather than losing text; explicit returns, tabs and page breaks remain boundaries. Save/RTF preserve the original spaces. Exact Windows spacing and overflow behavior remain unverified.
- Left/right/center/justified text, font size and colour, bold/italic/underline/strike formatting marks, hard returns, hard page breaks and fixed shad.
- The last alignment code on a line also applies when it follows the final character, precedes a return/page break, or ends the document. Save, RTF and native body exports retain these codes and repeated alignment changes. Exact Windows wrapping boundaries and group-scoped RTF paragraph behavior remain unverified.
- One tab interval with tab-aligned text, shared line baselines for mixed-size text, independent Tibetan raise, and nonprinting baseline/page-type-colour guides. Native page-type first-baseline offsets now import from BaseLineAdj; historical font metrics still need comparison.
- Automatic yi-go, Rinchen/Yang shad options, and final dzog thik with separate segment heights and inch/whitespace-percent rise controls. Exact edge behavior and whitespace endpoints still need Windows comparison.
- Duplex/manual/proof print preparation, reversed back rows, optional reverse back sheets, cut marks and test-sheet mode. Physical printer calibration remains necessary.
- Browser autosave, full web document save/open, separate web layout/content/annotation files. New text and text/PDF/RTF imports retain annotations, yi-go and fixed folio phrase.
- Unicode RTF body export with fonts/styles/colours and inline PNGs. Automatic marks, labels, page-attached images and pecha layout are excluded; inline image baseline/side spacing is not preserved by this exporter. RTF readers need suitable Tibetan fonts.

ADDED WEB WORKFLOWS (NOT CLAIMED ORIGINAL WINDOWS FEATURES)
- PDF extraction, legacy-font conversion where tables exist, Tibetan OCR and text repair.
- Unicode Tibetan and Wylie entry.
- Reversible whole-main-text size override that preserves fonts, bold and colours.
- Configurable root/commentary/heading styles. No fixed tradition-specific bold mapping.
- Ordered texts within a volume, independent Tibetan starts, continuous Arabic page numbers, section side names and text reordering.
- In pecha mode each section starts on a new folio front; an inserted blank back counts toward volume page numbers. Full-page mode starts a new page without a blank back. Restarting Title/Fancy layouts is an explicit per-text choice.

PARTIAL COMPATIBILITY
- Typeover: checkbox or unmodified Insert in the text editor replaces the next Unicode character cluster and appends at end of text. Formatting marks and line boundaries are preserved. Existing selections use normal replacement; paste and IME composition retain insertion, and combining marks extend the preceding character. Native browser undo/redo remains available. New/Close and body/document replacement return to Insert; applying layout/annotation settings keeps the editing mode. Original Insert-toggle and New/Close reset have static evidence; stacks, formatting and composition still need Windows runtime comparison.
- Recovery can save after each edit, every1/5/10/30 minutes, or be disabled. It stores one recovery in this browser, not a native .pxr file beside the source. Off retains the previous copy. Storage limits/private browsing can prevent recovery; keep downloaded copies.
- Close resets the next new pecha to web defaults and empty annotations; New/import while a document is open retains reusable annotations. Original startup settings are not imported.
- Revert restores the session open/full-Save checkpoint after confirmation. Full Save captures it when invoked, even if its download is cancelled. This does not reread an external file or retain earlier checkpoints across reloads. Browser recovery still stores recent edits automatically.
- Preview navigation: Go to Page uses document page numbers; Ctrl+G/Command+G focuses its field. Previous/Next browse all preview batches. Printing still includes the complete document. Native editor cursor behavior is not reproduced.
- Character selection: a Unicode Tibetan palette groups letters, subjoined forms, marks, signs and numbers, with optional supported typeface choice. It inserts at the cursor or replaces selection while preserving surrounding formatting. Experimental charts for 103 recognized names sharing 66 legacy font maps show byte slots in decimal/hex and insert the existing Unicode equivalents; missing, non-Tibetan and ambiguous four-zero mappings are disabled. Charts use substitute web fonts, not original glyph shapes. Ctrl/Command+I opens from the editor; Escape closes. Browser undo/redo is supported for picker insertion. Full legacy chart coverage, original source-font/history persistence, original runtime behavior and all Windows-installed fonts remain unverified.
- Full-page (non-pecha) mode reflows within paper margins, with separate line height and first baseline, one page per sheet, and yi-go after the first page. Pecha frames/labels are retained but hidden; original label interactions and native font/print equivalence still need verification.
- RTF body import retains Unicode, common single-byte code pages, mixed font/style/colour, breaks and PNG images while preserving current layout/notes. Tables are flattened; non-PNG pictures and embedded objects are skipped. Unsupported encodings, paragraph geometry and exact source font metrics remain incomplete.
- Custom yi-go accepts formatting marks; its font/emphasis can differ from the body, its size follows the first character, and its colour can follow that character or its own runs. Exact legacy rich-text paste behavior remains unverified.
- PXP import: five public examples are exercised, but not all settings, old font runs or images survive. Textual native image-header1.1 imports embedded PNG inline, yi-go and fixed-page images experimentally; version1.0 supports the observed28-byte asset/40-byte inline records. Six page anchors and one-based physical page numbers follow static format evidence. Framing/reference tests and browser import QA use synthetic specimens; no real native image specimen has been verified. Import notes remain visible above the preview during the session. No binary-format round trip is promised.
- Experimental PXT/PXC/PXA loading preserves the documented layout/content/annotation scopes. PXA0.1 bare keys and compact non-TCC fonts are supported from static writer evidence; inherited TCC slots normalize through the TibetanMachine conversion tables with an explicit source-font/glyph-verification warning. Annotation-file outside-note spacing is restored. Length-prefixed annotation text may contain section markers, and declared body lengths distinguish literal markers from appended images. LF/CRLF framing, scope and malformed-file isolation are regression-tested with synthetic fixtures; real native partial-file exports still need Windows verification.
- Named-font selection: common families, fonts used in body/volume sections, and an Other font name field. Font-only edits preserve other attributes; Save/Open and RTF retain the family. Local fonts must be available to avoid browser fallback; the app does not enumerate installed fonts.
- Formatted clipboard: the main editor copies/cuts selected RTF text and inline PNGs and pastes supplied RTF while restoring surrounding styles. Yi-go, fixed-phrase and margin-note fields accept supplied RTF and copy/cut selected formatted text. Cut preserves following styles, retains text on clipboard-write failure, and supports browser undo where available. Plain fields keep braces literal. Mark-field Copy/Cut uses 18 pt based on static evidence for the native entry controls. Printed yi-go still follows the page's first character, and printed notes/phrases use their configured sizes. Native clipboard baseline/default-font semantics still need runtime verification. Without RTF, paste uses plain text. Exact native deletion behavior, HTML conversion and real application-to-browser clipboard availability remain unverified.
- Editing: uses text plus visible formatting marks. Previous/Next mark navigation and selected line-break removal are available. The selected-text attribute panel changes only specified attributes, preserving mixed fonts, colours and styles and restoring the following text. It is not a direct-page WYSIWYG editor. Quick formatting chips still insert marks that continue until changed.
- Annotations: mixed runs use visible formatting marks rather than the original rich-text paste interface. Known native annotation formatting codes are imported; exact legacy fonts and all codes remain unverified.
- Templates: reusable web .pecha JSON plus experimental Windows .pxt layout export. PXT preserves numeric layout settings, not text, fonts, images, automatic marks or web styles. Automatic first-line placement becomes fixed; size/rotation conversions are reported. Windows opening and exact layout remain unverified. Native PXP/PXC/PXA exports are experimental and limited as described above.
- Printing: browser print/save-PDF. Match the paper size and orientation, use 100% scale and no margins, and disable browser headers/footers. Browser and printer settings can otherwise add pages or alter alignment.

- Native Arabic page-number fonts: full PXP imports retain the referenced named family (including Times New Roman in the bundled examples), with local fallback if unavailable. Web Save and annotation presets preserve it. Nonportable PXA/PXT font references retain the current family and report a warning. Exact Windows numeral appearance remains unverified.

NOT IMPLEMENTED YET
- Exact native pagination-based image pruning, original-app verification of all image exports, unobserved older record sizes, hidden native centered-page-image slot3, and exact original clipboard image semantics.
- Full TibetDoc/DCT import and export; only the bounded import described above is available. Complete Windows PXP/PXC/PXA interoperability remains unverified.
- TCC/Sambhota legacy keyboard maps; complete original locked-keyboard mapping, IME and undo parity.

- Command-line imports and Windows startup-INI/default-setting equivalence.
- Original direct-page editing and structured multilingual columns.
- Arbitrary page rearrangement within a text; reordering is by whole text section.

STILL TO VERIFY AGAINST WINDOWS
Exact Tibetan folio facing direction; rotation conventions; pagination and legacy font metrics; shad/yi-go/dzog edge cases; rich annotation behavior; all file-setting semantics. Missing documentation is not proof that a feature is absent from Windows.
